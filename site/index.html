DeepSeek Harness plugin

Run opencode as a subagent inside DeepSeek Harness.

One task leaves your conversation. opencode runs it in its own process, with its own models. The answer comes back. Nothing else does.

Two harnesses, one conversation.

DSH stays the driver. opencode brings its own models, tools and free tier, and nothing it does lands in your context or your token bill. The child receives the task text and the working directory. Not the history, not the plan, not the files it did not ask for.

Every run leaves a record.

The plugin speaks ACP itself, so it keeps the session id, model, duration, tool calls and tokens that the official provider drops. The last row is the failure worth keeping: it is the one that tells you what to fix.

Six frames. One answer.

DSH speaks ACP itself, so it can keep what the official provider drops: the session id on the child side, the model that ran, the duration, the tokens.

  1. initializeout

    Protocol version, client capabilities. The child agrees to speak ACP before anything is asked of it.

  2. session/newout

    A session is created inside opencode, bound to the directory the delegation was started from.

  3. session/promptout

    The task text crosses the boundary. That is the whole payload: no history, no attachments, no parent context.

  4. agent_message_chunkin

    The answer streams back as chunks. Only text is collected; tool traffic stays in the child's session.

  5. usage_updatein

    Tokens this run spent, recorded beside the model and duration when the answer lands.

  6. recordwrite

    Session id, model, milliseconds, tool calls, usage. Readable in the settings page as soon as the run settles.

Its free tier, not yours.

Refresh opencode's catalog from Settings, then spend one real request to test the saved model before you trust it. Free quota is per account and moves; the page tells you which model answered and which one refused.

Install it, then send one delegation.

Requirements: DSH >=0.2.1-rc.1 <0.3.0, opencode v2 with the acp subcommand, and an existing opencode login.

Add the plugin

dsh plugin --profile default add dsh-opencode-acp

Set the model

Settings → OpenCode 委派. Refresh the catalog, test one model, keep it.

Delegate

Ask your agent, or call subagent_opencode directly. The answer arrives as a completion notice.
